# Spectra Feature Parity Specification & Audit

This document provides a feature-by-feature evaluation comparing original **AyuGram Desktop** (`Telegram/SourceFiles/ayu/`) with the **Spectra** native Rust client rewrite.

| Feature | Required Behavior | Original Implementation | Proposed Rust (Spectra) Implementation | Protocol / API Limitations | Test Plan | Status |
|---|---|---|---|---|---|---|
| **Ghost Mode: Read Receipts Suppression** | Prevent Telegram servers from marking messages as read when viewed locally by the user. User can manually mark as read on demand. | `ayu_settings.h` (`sendReadMessages`), hooked in `History::applyRead` & `messages.readHistory` RPC. | `privacy/ghost.rs` intercepts viewport events. Omits `client.mark_as_read()` RPC unless manual trigger is activated. | Telegram DC keeps unread count on server until explicit RPC dispatch. | Unit test verifying RPC suppression when ghost mode enabled; integration test for manual mark-as-read. | **Supported** |
| **Ghost Mode: Typing Suppression** | Prevent sending "User is typing..." or "Uploading media..." status to peers. | `ayu_settings.h` (`sendUploadProgress`), hooked before `messages.setTyping`. | `privacy/ghost.rs` checks `should_send_typing()` before dispatching typing action to MTProto sender. | Fully client-side controlled; servers never receive typing packets. | Verify no outgoing `setTyping` packets emitted during composer input. | **Supported** |
| **Ghost Mode: Online Presence Suppression** | Prevent client startup or focus from broadcasting online presence status to contacts. | `ayu_settings.h` (`sendOnlinePackets`), suppresses `account.updateStatus(offline=false)`. | `privacy/ghost.rs` blocks presence update calls during connection and active loop. | Contacts see "last seen recently" or previous offline time. | Verify no `updateStatus(false)` calls are made on client initialization. | **Supported** |
| **Ghost Mode: Story View Stealth** | View posted user stories without sender appearing in viewers list. | `ayu_settings.h` (`sendReadStories`), drops `stories.readStories`. | Suppresses dispatch of `stories.readStories` RPC. | Story media is fetched without sending read receipt payload. | Mock story view and assert receipt packet is not scheduled. | **Supported** |
| **Anti-Recall (Deleted Message Retention)** | When a user or admin deletes messages "for everyone", preserve the message locally with full metadata and deletion timestamp. | `ayu/data/messages_storage.cpp` & `DeletedMessage` table in `ayudata.db`. | `storage/db.rs` marks existing message with `is_deleted = 1` and `deleted_at = now()`. UI renders red strikethrough with `[DELETED]` badge. | Deletions cannot be recovered if client was offline and never fetched the message originally. | Unit tests inserting message, executing `mark_deleted`, verifying persistence and query retrieval. | **Supported** |
| **Anti-Edit (Message Revision Tracking)** | Retain full chronological revision history of all message text edits. | `ayu/data/messages_storage.cpp` & `EditedMessage` table in `ayudata.db`. | `storage/db.rs` records prior drafts in `message_edits` before applying update. UI provides clickable `[EDITED]` badge with revision popover. | Captures revisions observed while client is running; edits prior to first sync show current text only. | Unit test updating message text multiple times and asserting chronological revisions list. | **Supported** |
| **Deleted Dialogs Preservation** | If a peer deletes a secret chat or private dialog, preserve chat info and message archive. | `DeletedDialog` table in `ayudata.db`. | `storage/db.rs` maintains `is_deleted` flag on `chats` table. | Cannot sync new server messages for deleted channels. | Unit test deleting dialog and confirming messages remain accessible in local archive. | **Supported** |
| **Protected Content Bypass (`noforwards`)** | Allow copying, forwarding, and saving media from channels where admin disabled forwarding. | Bypasses `chat->noforwards` check in UI actions. | UI ignores `noforwards` flag in context menus and download actions. | Client-side enforcement only in official clients; MTProto servers serve media identical to normal chats. | Test copy & save actions on mock messages marked with `noforwards = true`. | **Supported** |
| **Expiring View-Once Media Retention** | Retain self-destructing/TTL media indefinitely. | Clones media file from cache before TTL destruction timer fires. | Immediately persists incoming media files to unmanaged app data storage upon arrival. | Must capture media before client receives TTL expiration or purge trigger. | Test with mock TTL message, verify saved file persists on disk. | **Supported** |
| **Streamer Mode & Sensitive Data Masking** | Conceal phone numbers, balances, and chat titles when screen recording or streaming. | `features/streamer_mode/` replacing strings in UI drawing routines. | Adw UI theme setting masking sensitive account handles and phone numbers. | Purely UI presentation layer. | Test UI toggle and verify redacted labels in header and profile views. | **Supported** |
| **Custom Themes & Adw Integration** | GTK4 Libadwaita dark/light styling, accent colors, custom font scaling. | AyuGram custom Qt palette engine (`ui/utils/palette.cpp`). | Libadwaita `AdwStyleManager` with custom CSS provider for message bubbles. | Fully supported in modern Linux desktop environments. | Visual verification of light/dark mode and bubble CSS rendering. | **Supported** |
